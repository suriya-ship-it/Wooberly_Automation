# Release Notes - Version 1.0

**Release Date:** 2026-10-05  
**Component:** Appium Mobile Automation - Wooberly Rider  
**Script Target:** `tests/wooberly_login.ts`

---

## 1. Overview
Version 1.0 delivers the initial mobile test automation suite for the Wooberly Rider Android application (`com.radicalstart.wooberly`). This release automates the onboarding and authentication journey up to the OTP verification step using WebdriverIO and Appium UiAutomator2.

---

## 2. Key Features & Automation Flow

1. **Appium Session Initialization**:
   - Automated driver connection to local Appium 2.x server running on port `4723`.
   - Android capabilities configured:
     - `appPackage`: `com.radicalstart.wooberly`
     - `appActivity`: `com.radicalstart.wooberly.MainActivity`
     - `automationName`: `UiAutomator2`
     - `noReset`: `true` (preserves existing state)
     - `autoGrantPermissions`: `true`

2. **Welcome Screen ("Get started")**:
   - Identifies and clicks the `"Get started"` button (`//android.widget.ImageView[@content-desc="Get started"]`).

3. **Phone Number Input**:
   - Locates the mobile number input field (`//android.widget.EditText`).
   - Inputs test phone number: `9876543210`.
   - Dismisses software keyboard using accessibility action (`~Done`).

4. **Terms & Conditions Acceptance**:
   - Locates and selects the required terms and conditions checkbox widget.

5. **Phone Number Verification**:
   - Clicks the `"Verify"` button (`~Verify`).
   - Waits for the SMS/OTP verification screen to load.

6. **OTP Auto-fill & Proceed**:
   - Interacts with the auto-fill OTP option (`~Your OTP is 1234`).
   - Emits keycode 66 (Enter) to dismiss keyboard obstructing the proceed action.
   - Clicks `"Proceed"` button (`~Proceed`).

7. **Verification Artifacts**:
   - Automatically captures screenshot of the transition to the profile details screen:
     - Saved to: `./screenshots/profile_details_screen.png`.

---

## 3. Technical Discoveries & Fixes

- **Permission Dialog Handling**: Handled blocking system permission dialogs (Location and Notification permissions) via ADB pre-grants:
  - `android.permission.ACCESS_FINE_LOCATION`
  - `android.permission.POST_NOTIFICATIONS`
- **Keyboard Obstruction**: Identified that the Android on-screen keyboard overlaps the `"Proceed"` button. Resolved by dispatching keycode 66 to dismiss the IME before clicking.
- **OTP Auto-fill Targeting**: Discovered that direct `setValue` on the individual OTP character fields is unreliable due to Flutter's custom PIN view implementation; leveraged the accessibility ID `"Your OTP is 1234"` for 100% reliable auto-fill.
