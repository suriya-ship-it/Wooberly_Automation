## 2. Issues Addressed & Root Causes

### 1. Flutter IME Focus vs. Appium `setValue()`
- **Issue:** Standard `element.setValue()` actions executed without errors in Appium logs, but the input fields visually remained blank and the values were not registered in Flutter's `TextEditingController`.
- **Root Cause:** In Flutter on Android, `TextFormField` requires an active `FocusNode` and an open Input Method Editor (IME) channel. When Appium's UiAutomator2 performs `elementClear` and `elementSendKeys` via Android Accessibility without focusing first, Flutter redraws the widget tree from its internal Dart controller (which remains empty).
- **Resolution:** Explicitly tap each input field (`element.click()`) to request focus and open the IME connection, type using keystrokes (`driver.keys()`), and cleanly dismiss the keyboard (`driver.pressKeyCode(4)`).

### 2. Location Field Architecture (Google Places Autocomplete)
- **Issue:** Attempting to type directly into the "What's your location?" field failed.
- **Root Cause:** In `Wooberly_Rider_V3.5/lib/views/namefields.dart`, the location field is marked `readOnly: true, enabled: false` and wrapped in an `InkWell`. Tapping it routes via GetX to `AppRoutes.APP_CITY_SEARCH` (`Wooberly_Rider_V3.5/lib/views/google_place_search.dart`).
- **Resolution:** 
  1. Click the location container (`locationField.click()`).
  2. Wait for `CitySearch` view to appear.
  3. Type `"Madurai, India"` into the search bar.
  4. Wait for Google Places API predictions to populate.
  5. Select the predicted suggestion (`~Madurai, Tamil Nadu, India`), which fetches geographic coordinates and returns to the details form.

### 3. Last Name Character Length Validation
- **Issue:** The requested input `"kb"` for Last Name caused form submission to be rejected.
- **Root Cause:** In `namefields.dart` (`validateLastName()`), the app evaluates:
  ```dart
  !(value.trim().length > globals.nameLength[0] - 1 && value.trim().length - 1 < globals.nameLength[1])
  ```
  `globals.nameLength[0]` defines the minimum length as **3 characters**. Entering `"kb"` (2 characters) triggers an in-app SnackBar:
  > *"Last name must be within 3 to 50 characters"*
- **Resolution:** Updated test input to `"kbb"` (3 characters), satisfying the validation requirement.

### 4. Confirm Password Visibility & Scroll Gesture
- **Issue:** The "Confirm password" field was partially obscured by the floating "Finish" button and off-screen.
- **Root Cause:** The Finish button is pinned to the bottom of the viewport using `Stack` and `Align(alignment: Alignment.bottomCenter)`. The form inputs reside inside a `SingleChildScrollView`.
- **Resolution:** Added a vertical swipe/drag gesture using W3C pointer actions (`driver.action('pointer')`) to scroll down 600px, bringing both "Password" and "Confirm password" cleanly into the interactable viewport.
