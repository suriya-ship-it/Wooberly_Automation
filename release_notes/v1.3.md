# Release Notes v1.3

## Changes and Fixes
- **Location Selection Flow Fixed**: The script now successfully navigates the native "Where to go" and Map Confirmation pages.
- **Identified Flutter Accessibility Issue**: Discovered that the `Done` button on the "Where to go" page has a massive bounding box in the accessibility tree that covers the entire screen (Y=277 to 2273). When Appium clicked the center of this box (Y=1275), it accidentally clicked the `Add work` button instead of `Done`.
- **Coordinate-based Clicks**: Replaced `driver.$('~Done').click()` and `driver.$('~Confirm location').click()` with coordinate-based pointer actions (`x: 500, y: 2100`) to guarantee that the actual buttons at the bottom of the screen are tapped.
- **Dynamic Map Confirmation Loop**: Enhanced the map confirmation loop to wait dynamically (up to 15 iterations, or ~1 minute) and retry if the map is still loading, ensuring it doesn't break out prematurely before the map finishes rendering.
- **Category Page Detection**: Added a strict break condition to correctly exit the confirmation loop only when the `Book now` or `Confirm` buttons (from the Category Selection page) are found.

## Known App Behaviors (Not Script Bugs)
- **Map Pages are Native Flow**: After clicking "Done" on the prediction screen, the application natively transitions to Map pages for both Pickup and Dropoff to ask the user to confirm the location. This is a mandatory app flow, not a script error.
- **Multi-stop Loop**: As per user instruction, the `+` icon multi-stop logic has been deferred to a later phase.
