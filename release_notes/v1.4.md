# Release Notes - Version 1.4: "During Booking" Driver & Rider Integration

**Release Date:** October 12, 2026  
**Status:** Released  
**Scope:** Dual-App Orchestration (`wooberly_combined_driver_rider_flow.ts`), Driver Online Automation (`wooberly_driver_online_flow.ts`), "Already Logged In" State Bypass, and Test Command Documentation ([`docs/test_commands.md`](file:///Users/radicalstart/Documents/appium-automation/docs/test_commands.md)).

---

## 1. Overview
Version 1.4 introduces the **"During Booking"** automation phase, establishing synchronized cross-app testing between the **Wooberly Driver** application ([`apps/wooberly_driver.apk`](file:///Users/radicalstart/Documents/appium-automation/apps/wooberly_driver.apk)) and the **Wooberly Rider** application. 

Additionally, this release implements a resilient **"Already Logged In" state detection** across all test suites, enabling test scripts to skip redundant landing, phone entry, profile signup, and OTP verification steps if an active session is already detected.

---

## 2. Key Features & Additions

### A. Driver Online Flow Automation (`wooberly_driver_online_flow.ts`)
- **Driver Authentication**: Launches `com.radicalstart.wooberlydriver`, handles country code (`+91`), phone entry (`7639699826`), terms checkbox, push notification dialogs, and OTP verification (`1234`).
- **Comprehensive Permission Orchestration**:
  1. Detects and clicks `"Go"` button to open the location access dialog.
  2. Handles in-app `"Got it"` / `"While using the app"` permission prompts.
  3. Navigates to Android System Settings via `"Go to settings"` link.
  4. Interacts with OS settings: Permissions -> Location -> **"Allow all the time"**.
  5. Performs double-back navigation (`driver.back()`) to return to the Driver app.
  6. Rejects battery optimization (`"Deny"`) and app invoke dialogs.
  7. Taps final `"Go"` button to transition the driver state to **Online**.

### B. Dual-App Orchestration Flow (`wooberly_combined_driver_rider_flow.ts`)
- Configured dedicated npm script: `npm run test:during-booking`.
- Automates the complete cross-app journey:
  1. **Phase 1 (Driver Online)**: Brings Driver app online with background location permissions configured.
  2. **Phase 2 (Rider Booking)**: Activates Rider app in the foreground, searches destination ("Mattuthavani madurai"), chooses vehicle category, confirms Cash payment, and dispatches booking request.
  3. **Phase 3 (Driver Ride Acceptance)**: Activates Driver app in the foreground upon nearby driver dispatch, detects the incoming trip notification/modal, and triggers the **"Accept"** button action.

### C. "Already Logged In" Bypass Logic
All test scripts now proactively inspect the current screen before executing authentication:
- **Driver App Detection**:
  - Checks for `"Go"`, `"GO"`, `"offline"`, or `"online"` indicators.
  - If detected, immediately skips "Get started", phone entry, and OTP verification, proceeding directly to the "Go Online" permission flow.
- **Rider App Detection**:
  - Checks for `"Where to?"`, `"Search your destination"`, or `"Where are you going?"` home map indicators.
  - If detected, skips landing, phone entry, profile details, and OTP verification, proceeding straight to ride booking.
- **Applied Across All Scripts**:
  - `tests/e2e/wooberly_combined_driver_rider_flow.ts`
  - `tests/e2e/wooberly_driver_online_flow.ts`
  - `tests/e2e/wooberly_login_e2e_flow.ts`
  - `tests/e2e/wooberly_e2e_flow.ts`

### D. Test Commands Documentation ([`docs/test_commands.md`](file:///Users/radicalstart/Documents/appium-automation/docs/test_commands.md))
